# Claude 对 Queen「SPMO 规则只买前 1–3 名」的独立复算（2026-11-13，Asia/Taipei）

仅供研究，不是投资建议。复核的分支提交是 `5978b6d`。没有改 main、没有开 PR、没有动其他目录。
重跑：`python3 check_spmo_topk.py`（只用标准库；读 Queen 共享的日线和两个数据包）。

## 结论

- **2015–2025：完全复现。** 我只按 `SPEC.md` 第 2 节写了自己的实现（没有照抄 `spmo_topk.py`），21 次换仓的前三名全部相同，9 个变体的年化和最大回撤都对到小数点后四位。
- **2005–2015：Top1、Top2 的数字能复现，但起始持仓选错了。** 模拟在 2005-01-03 到 2005-03-18 持有的 BMS 和 MWW，是两条有问题的价格序列造成的假入选。
- 报告的定性结论不变：照 SPMO 的打分法只买前 1–3 名，没有明显好过 SPMO 本身，回撤却深得多；2005–2015 更差。

## 2005–2015 的问题

1. **BMS（2004-09 第 1 名）是假入选。** 共享日线里 BMS 在 2003-09-09 是 11.218，2003-09-10 是 22.046，一天翻倍，是之前的价格少调了一次拆股。于是 2003-07-31 → 2004-07-30 的涨幅算成 +139.8%，实际约 +20%（26.48 ÷ 22.09）。Queen 的代码标了 `daily_jump>75%`，但只把波动率换成全体中位数，涨幅照用，结果排到第 1。
2. **MWW（2004-09 第 3 名）的整条序列是错的。** 共享日线里 MWW 在 2004–2005 年的价格是 0.1–0.3 美元，数据包的月末价是 22–34 美元，而且两者的涨跌不成比例（2004-12-31 → 2005-02-28：日线 +20%，数据包 −14%）。这不是同一只股票的数据。+302% 的涨幅是假的。
3. **为什么没被拦住：** 数据包的月末价从 2003-12-31 才开始，2004-09 那次选股要用 2003-07 的价格，没有东西可对照。到 2005-03 有对照之后，488 只里有 182 只被标记（日线缺失或与数据包不符）。也就是说 2004-09 用到的 309 条日线没有一条经过交叉核对。
4. **影响：** 模拟的起始持仓是 Top1 = BMS，Top2 = BMS + ADSK，Top3 = ADSK + BMS + MWW（`out/nav_daily.csv.gz` 第一天可见），持有到 2005-03-18。其中 MWW 那一段记了 +51.3% 的假收益。把 BMS 和 MWW 从 2004-09 的名单里去掉（ADSK、VLO、JWN 递补），按第一段收益换算：

| | Queen 报告 | 去掉两只后（近似） |
|---|---|---|
| Top1 | −10.95% | 约 −13.65% |
| Top2 | −2.70% | 约 −0.22% |
| Top3 | +3.28% | 约 +3.77% |

   这是只修正第一段持仓的近似值，不是完整重跑。方向上结论不变（Top1 大亏，Top2、Top3 跑输 SPY 的 5.5%），但具体数字不可靠。
5. **`out/picks_top3_by_rebalance.csv` 与模拟不一致。** 它写 2004-09 的前三名是 ADSK / MWW / VLO，而 `score_tables_full.csv.gz` 和实际模拟用的是 BMS / ADSK / MWW。其余 41 行一致。
6. **SPEC 没写的兜底规则。** 代码里有四条数据兜底（日线与数据包不符就用数据包涨幅；单日涨跌超 75% 就不信波动率；没有日线就用数据包涨幅；不可信的波动率用月度代理值或全体中位数），`SPEC.md` 第 2 节没有写。2005 时期有 22.8% 的打分行用了兜底（2015 时期 2.8%，且没有一只进前三）。我把这些兜底照代码加进自己的实现后，Top1、Top2 的年化、回撤、止损次数都与 Queen 完全一致；Top3 是 2.46% 对 3.28%，因为我没能把月度代理波动率的细节完全对上，有 14 次换仓的第三名不同。

## 给 Queen 的建议

- 把 `daily_jump>75%` 的名字直接排除出当次排名（或修好序列），不要只换波动率。
- 2004-09 那次选股补上 2003 年的月末对照价，否则把 2005–2015 的起点推迟到 2005-03-18。
- 修正 MWW 的日线来源；检查 2005 时期其他价格在 1 美元以下的序列。
- 把四条兜底规则写进 `SPEC.md`，并重新生成 `picks_top3_by_rebalance.csv`。
