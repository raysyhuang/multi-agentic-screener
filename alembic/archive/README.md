# Archived migrations (pre-baseline history)

These sixteen revisions are the migration history from February to August 2026.
They are kept for provenance and are **not on the version path** — alembic only
loads `alembic/versions`, so nothing here is ever executed.

## Why they were archived

The chain they formed could not build a database from nothing. Its root,
`e9b5089b0025` (2026-02-17), was autogenerated against a database that
`Base.metadata.create_all` had already created, so it opened with

```python
sa.ForeignKeyConstraint(['signal_id'], ['signals.id'], )
```

while no migration in the chain ever created `signals`. Nine core tables were in
that position:

    agent_logs   candidates   daily_runs   divergence_events   divergence_outcomes
    near_misses  outcomes     pipeline_artifacts               signals

Five later revisions then added columns to those never-created tables, so the
chain was internally consistent only against a pre-existing database.

`alembic upgrade head` on an empty database failed with
`UndefinedTableError: relation "signals" does not exist`. The practical
consequences were that production's schema was not reproducible from source,
no environment could be rebuilt or stood up the way production was built, and
CI had no alembic step, so none of this was visible for six months.

They were replaced by a single squashed root, `0001_baseline`, generated from
the ORM metadata and proven by the `migrations` CI job
(`alembic upgrade head` → `alembic check` → `downgrade base` → up again).

## Restoring one

Don't move a file back into `alembic/versions/`. It would rejoin the chain as a
second root and reintroduce exactly the split-history failure above — a database
can report "at head" on one chain while missing the other's tables.
`tests/test_db/test_migration_baseline.py` fails if that happens.

Read them here for history; write new migrations against `0001_baseline`.

## Databases created before the squash

They already have this schema. Stamp, do not upgrade:

    alembic stamp 0001_baseline

Long-lived databases also carry `cross_engine_synthesis` and
`multi_engine_backtest_runs`, created by archived revisions and orphaned by the
2026-07 cross-engine strip. The ORM does not declare them and no code reads
them, so the baseline does not create them and a freshly built database will not
have them. The stamp asserts that the baseline's tables are present and
correctly shaped — not that nothing else is.
